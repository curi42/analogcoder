# `two_stage_opamp` 의 바이어스 체인은 DC 해가 둘이다 — 2026-07-30

**`benchmarks/two_stage_opamp/netlist.cir` 의 자기 바이어스 체인은 안정한 DC 해를
두 개 갖는다. 솔버가 어느 쪽으로 가는지는 소자 크기와 코너에 혼돈적으로
의존하고, 두 상태의 AC 응답은 UGBW 기준 13배 다르다. 출하된 45코너 데이터가
이미 영향을 받고 있다 — 127개 측정값이 상태에 따라 달라진다.**

발견 경로: T8(판별력 있는 벤치마크)의 노브 결합 스캔에서 `X6.W` 가 특정 값일 때
`ugbw_hz` 가 한 자릿수 점프하는 것을 보고 추적했다.

---

## 1. 무엇이 관측됐는가

`X6.W`(출력단 NMOS 폭)를 촘촘히 훑으면 **고립된 단일 값**에서만 이상이 난다.

| `X6.W` | `ugbw_hz` | `phase_margin_deg` |
|---|---|---|
| 5.0 | 2.069e6 | 33.82 |
| **5.5** | **2.662e7** | **27.70** |
| 5.9 | 2.074e6 | 34.08 |
| **6.0** | **2.695e7** | **28.39** |
| 6.1 | 2.075e6 | 34.13 |
| 8.0 (출하값) | 2.080e6 | 34.56 |
| 26.0 | 2.034e6 | 34.89 |
| **27.0** | **2.982e7** | **35.78** |
| 28.0 | 2.027e6 | 34.83 |

배제한 가설 셋, 전부 실측으로:

- **`meas` 의 다중 교차 오선택이 아니다.** `cross=1` 을 붙여도 값이 바뀌지
  않고, `print vdb(vout)` 로 직접 세어 보면 0 dB 교차가 각 경우 **정확히 1회**다.
- **sky130 소자 bin 경계가 아니다.** `5.999999` 정상 / `6.0` 이상 /
  `6.000001` 정상 — 측도 0 의 집합이고 bin 은 구간이다.
- **비결정론이 아니다.** `W=6.0` 을 새 프로세스로 5회 돌려 전부 같은 값이 나온다.

## 2. 원인 — 바이어스 체인이 두 상태를 갖는다

`op` 로 동작점을 직접 찍으면 갈라진다.

| 노드 | 상태 A (정상) | 상태 B (이상) |
|---|---|---|
| `nbias` | 0.5399 | 0.6740 |
| `pbias` | 0.9129 | 0.7324 |
| `tail` | 1.5007 | 1.6406 |
| **`degn`** | **0.0119** | **0.0626** |
| `vout` | 0.5508 | 0.5512 |

`degn` 이 `Rdeg degn vss 20k` 위의 전압이므로 곧 바이어스 전류다: 상태 A 는
~0.6 µA, 상태 B 는 ~3.1 µA. **5.3배**다. 그 전류가 입력쌍의 `gm` 을 정하고,
밀러 보상된 2단 증폭기의 UGBW ≈ `gm1 / (2π·Cc)` 이므로 UGBW 가 13배 뛴다.

`Xn2 nbias nbias degn vss` + `Rdeg` 는 자기 바이어스 전류원(beta-multiplier)이고
그 구조는 고전적으로 다중 해를 갖는다. `Rstart vdd nbias 3Meg` 가 시동 소자이지만
**두 상태 모두 전류가 흐르므로** 이것은 "영전류 축퇴 상태" 문제가 아니다 —
동작하는 상태가 둘이다.

**`vout` 이 양쪽 다 0.55 V 다.** 피드백이 출력을 잡고 있으므로 DC 출력만 보면
차이가 안 보인다. AC 응답만이 드러낸다.

## 3. 이것이 왜 중대한가

**튜너는 소자 크기를 바꾼다.** 크기를 움직이다 상태가 뒤집히면 판정자는 UGBW 가
13배 다르고 위상 여유가 6° 다른 값을 받는다 — **같은 회로의 다른 동작점에서 잰
값을 같은 설계의 값으로 읽는다.** 그리고 아무 기록도 남지 않는다.

이 저장소가 이미 세 번 지불한 부류다: 결함 #10(PWL 공급 재작성이 조용히 no-op
이 되어 전압 축이 죽음), `mult` vs `m`(PNP 배수가 아무 일도 안 함),
`.option scale`(W 를 미터로 읽음). **측정이 조용히 다른 것을 재는 것**이
게이트가 조용히 무력한 것보다 나쁘다.

CLAUDE.md 와 설계 문서들이 이 덱에서 뽑은 수치를 여럿 인용한다 — `Cc` 스윕 표,
PSR 기준선(`psr_plus_db` −15.12, `psr_minus_db` −3.36), "Claude 가 `Cc`+`M6.W`
조합으로 2 이터레이션에 풀었다"는 실행. **그 실행은 `M6.W` 를 움직였다.**
어느 상태에서 잰 값인지 확인된 바 없다.

## 4. 출하된 데이터가 이미 영향을 받는다

`.nodeset` 으로 상태 A 를 유도한 덱과 현행 덱의 **45코너 × 4테스트벤치** 스윕을
비교했다.

```
현행    overall_pass: False
nodeset overall_pass: False
총 다른 측정값: 127
```

예시(전부 출하값 `X6.W=8`, 소자 크기를 건드리지 않은 상태):

| 코너 | 측정값 | 현행 | nodeset |
|---|---|---|---|
| `tt/1.62/27` | `t_lo_last` | 1.033e-6 | **2.805e-6** |
| `tt/1.62/27` | `t_hi_last` | 1.048e-6 | **3.081e-6** |
| `tt/1.8/-40` | `psr_plus_db` | −9.319 | −9.961 |
| `tt/1.8/-40` | `psr_minus_db` | −1.708 | −1.948 |
| `tt/1.8/-40` | `ugbw_hz` | 1.8516e6 | 1.8613e6 |

**판정은 바뀌지 않는다**(양쪽 다 `overall_pass: False`) — 그러나 개별 값은
바뀌고, `t_lo_last` 는 2.7배다. 즉 **코너를 바꾸는 것만으로도** 상태가 뒤집힌다.
소자 크기는 필요하지 않다.

## 5. 검증된 완화책 — 그리고 왜 적용하지 않았는가

`.nodeset v(xdut.nbias)=0.5399 v(xdut.pbias)=0.9129` 를 덱에 더하면:

| `X6.W` | 현행 ugbw | nodeset ugbw |
|---|---|---|
| 4 | 2.063e6 | **2.063e6** (동일) |
| 5.5 | 2.662e7 | **2.072e6** (고쳐짐) |
| 5.999999 | 2.075e6 | **2.075e6** (동일) |
| 6.0 | 2.695e7 | **2.075e6** (고쳐짐) |
| 8 | 2.080e6 | **2.080e6** (동일) |
| 27 | 2.982e7 | **2.030e6** (고쳐짐) |
| 30 | 2.019e6 | **2.019e6** (동일) |

**이상했던 값 전부가 매끄러운 추세로 돌아오고, 정상이던 값은 전부 동일하다.**
`.nodeset` 은 뉴턴 반복의 **초기 추정**일 뿐이므로 최종 해는 여전히 진짜 DC 해다 —
답을 강제하는 것이 아니라 어느 분지로 갈지를 유도한다.

**적용하지 않은 이유:** 이 변경은 45코너 데이터의 **127개 값**을 바꾸고, CLAUDE.md
와 두 설계 문서가 인용하는 수치들의 근거를 바꾼다. 그리고 "어느 상태가 의도된
것인가" 는 설계 판단이다 — 출하값 `X6.W=8` 의 nominal 이 상태 A 이고 문서화된
기준선과 맞으므로 A 가 의도된 것으로 **추정**되지만, 확인된 바는 아니다.
벤치마크의 의미를 바꾸는 결정이므로 사람이 정해야 한다.

## 6. 무엇을 정해야 하는가

1. **상태 A 가 의도된 동작점인가?** 상태 A 는 ~0.6 µA, B 는 ~3.1 µA 다. 설계
   의도를 아는 사람이 답해야 한다.
2. **`.nodeset` 으로 고칠 것인가, 시동 회로를 제대로 넣을 것인가?** `.nodeset`
   은 시뮬레이션 힌트이고 실물 회로의 다중 해를 없애지 않는다. 밴드갭 벤치마크는
   같은 문제에 `BGR_CORE.Xsu_b`(항상 켜진 트리클)로 대응했고, CLAUDE.md 가 그
   근거를 적는다.
3. **고치면 문서화된 수치를 어떻게 할 것인가?** 재측정하고 문서를 갱신해야 한다.
   그 수치를 인용하는 자리: CLAUDE.md 의 `two_stage_opamp` 절, PSR 설계 문서
   (`2026-07-25-psr-verification-design.md`), 2단 op-amp 설계 문서
   (`2026-07-25-two-stage-opamp-benchmark-design.md`).
4. **고치기 전에도 탐지는 값어치가 있는가?** 상태 B 는 `degn` 으로 명확히
   구별되므로, 컨트롤 블록에 `let ibias = v(degn)/20k` 한 줄과 기준 하나를 더하면
   상태가 뒤집힌 실행이 **판정에서 드러난다.** 이것은 덱의 의미를 바꾸지 않고
   추가만 하는 것이므로 위 셋과 독립으로 할 수 있다.
