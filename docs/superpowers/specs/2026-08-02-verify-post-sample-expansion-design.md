# verify_post 표본 확장 — 사전 등록

작성 2026-08-02, **결과를 보기 전에 고정한다.** 이 문서를 커밋한 뒤에 런을 돌린다.

## 왜 다시 재는가

2026-08-01 의 재생 측정은 `runs/*/history.jsonl` 의 verify_post 결정 26 건을
사전 등록 규칙 D/G/I 로 재생했고, **전건 일치 규칙이 없어 verify_post 유지**로
끝났다. 그 판정은 유효하고 뒤집지 않는다. 다시 재는 것은 판정을 바꾸기
위해서가 아니라 **그 측정의 표본이 사실상 단일 런이었기 때문**이다.

| 사실 | 값 |
|---|---|
| verify_post 결정 | 26 |
| LLM 이 rollback 을 권고한 건 | 7 |
| 그중 `runs/pvt_sonnet_1` 하나에서 나온 건 | **6** |
| 나머지 1 건 | `pvt_verification_1` — before/after 숫자가 완전히 동일 |

즉 **결정을 가르는 사건이 한 런에 몰려 있고**, 그 런은 최종 스윕에서 7 개
기준을 전부 실패하고 FAIL 로 끝난 런이다. D1 을 무효로 만든 것과 같은 모양이다.

추가로, 앞선 측정에서 드러난 사실 하나를 여기 기록한다: **가장 싼 후보 규칙인
D(`regressed_between`, pass 플립)는 26 건 전부에서 `keep` 을 반환했다.** 기록된
역사 전체에서 pass 가 뒤집힌 스텝이 한 건도 없다. 이 저장소가 "조용히 무력한
게이트"라 부르는 모양이며, 결론은 **"회귀 판정이 이미 결정론이니 그것으로
대체하면 된다"는 길이 막혀 있다**는 것이다. 실제 rollback 은 전부 마진 판단이다.

## 무엇을 답하려는 것이고, 무엇은 포기하는가

세 질문 중 하나만 답한다. 나머지 둘을 포기하는 것도 여기 등록한다.

- **A. LLM 이 측정값 밖의 것을 보는가** — 재생으로 답할 수 있다. **이번 대상.**
- **B. 규칙이 LLM 만큼 좋은 결정을 하는가** — 원리적 반례로 상한만 보인다.
  규칙 I 를 한 건으로 기각한 방식. 이번에 부수적으로만 본다.
- **C. 규칙으로 돌린 런이 LLM 런만큼 수렴하는가** — **이 저장소 규모에서
  포기한다.** 근거 셋: (1) 튜너가 확률적이라 두 런이 verify_post 때문이 아니라
  튜너 때문에 갈라진다; (2) D1 이 같은 벽에서 답을 만든 기법인 페어드 프로브는
  **결정이 상태를 바꾸지 않을 때만** 성립하는데 verify_post 의 결정은 곧 다음
  iteration 의 덱이다; (3) "어느 결정이 옳았나"의 정직한 정의가 "그 덱에서 계속
  갔을 때 통과했나"뿐이라, C 를 재는 방법이 C 를 돌리는 것 자체다.

  C 를 포기해도 되는 이유는 **verify_post 가 판정 경로가 아니라 탐색 경로에 있기
  때문**이다. judge 는 틀리면 거짓 값이 `result.json` 에 실렸고 실제로 25 건을
  지어냈다. verify_post 가 틀리면 덜 좋은 덱에서 다음 iteration 을 시작할 뿐이고,
  최종 전체 스윕은 여전히 실제 덱을 잰다. 비용이 유계이고 알려져 있다.

## 돌릴 런 — 결과와 무관하게 고정

코너 스윕이 없는(= 싼) 스펙만 쓴다. 여섯 개 전부 `pvt_corners` 미선언을 확인했다.

| 스펙 | 반복 | 고른 이유 |
|---|---|---|
| `bandgap/spec_seed_tc.yaml` | 2 | 의도적으로 **결합된** 시드 — `Rp/R1` 이 TC 를 고치면서 `vbgout`/`vbg1` 을 끌고 간다. 회귀가 구조적으로 발생한다 |
| `bandgap/spec_seed_buf0_droop.yaml` | 2 | 기존 런이 4 iteration 을 썼다 — 지금까지 pvt 외에서 결정을 가장 많이 낳은 스펙 |
| `bandgap/spec_seed_trim_pm.yaml` | 2 | 세 시드 중 나머지 하나. 시드별 편향을 피한다 |
| `two_stage_opamp/spec.yaml` | 2 | psr 트레이드오프가 문서화되어 있다 — `M6.W` 가 `psr_minus` 를 고치며 `phase_margin` 을 되돌린다. 설계상 rollback 생성기 |
| `two_stage_opamp/spec_topology_required.yaml` | 2 | `Cc` 만으로는 도달 불가한 목표. 실패 경로가 길다 |
| `bandgap/spec_seed_topology.yaml` | 2 | 스왑 경로에서의 verify_post 를 표본에 넣는다 |

**총 12 런.** 런 디렉터리는 `runs/vp_<spec>_<n>/`.

**비용 규칙**(결과가 아니라 시간에만 의존하므로 사전 고정해도 편향이 없다):
런 하나가 **20 분**을 넘기면 그 스펙은 1 회만 돌리고 두 번째를 취소한다.
취소했다는 사실과 취소한 스펙을 결과에 반드시 적는다.

**런을 골라내지 않는다.** FAIL 로 끝난 런, 크래시한 런, verify_post 결정이 0 건인
런도 전부 표본에 포함한다. 결과가 마음에 안 든다고 런을 추가하지 않는다.

## 재생 코드

`verify_post_rules.py` 의 규칙 D/G/I 와 정규화 코드를 **한 글자도 바꾸지 않는다.**
새 런이 생긴 뒤 같은 스크립트를 그대로 다시 돌린다. 스크립트가 `runs/*` 를
전부 읽으므로 기존 26 건과 새 표본이 합쳐진다. 기존 26 건을 빼지 않는다.

## 판정 규칙 — 결과를 보기 전에 고정

합쳐진 전체 표본에서 규칙 G 의 불일치를 본다. 각 불일치는 셋 중 하나로 분류된다.

- **(a) 결정론적으로 불가능** — before 와 after 의 정규화 슬랙 벡터가 동일한 건.
  입력이 같으므로 어떤 결정론 함수도 두 답을 낼 수 없다. 규칙의 실패가 아니다.
- **(b) 잡음 바닥 이하** — 개선/악화의 크기가 이 저장소가 이미 측정해 둔
  `COMPARISON_REL_TOLERANCE = 1e-3` **미만**인 건. 이 상수는 오늘 고르는 값이
  아니라 `curation.py` 에 이미 있는 측정된 값이다.
- **(c) 진짜 판단 차이** — 위 둘 중 어느 것도 아닌 건.

판정:

1. **G 가 전건 일치** → 대체 후보로 승격. 다음 단계는 원리 검토(B).
2. **불일치가 전부 (a) 또는 (b)** → "G 는 숫자로 설명되는 범위에서 LLM 과
   일치한다"로 기록하고, **잡음 바닥을 붙인 G′ 를 다음 라운드의 새 사전 등록으로
   올린다. 이번 라운드에서 G′ 를 채택하지 않는다.** 지금 데이터로 임계값을 붙이면
   그것은 데이터에 규칙을 맞추는 것이고 이 저장소가 금지한 사후 규칙 변경이다.
3. **(c) 가 한 건이라도 있으면** → **verify_post 유지.** 그 건의 숫자를 기록한다.

**표본 규칙(일치율과 독립):** 새 런의 rollback 권고가 **2 개 이상의 서로 다른
런**에 분산되지 않으면, 위 판정과 무관하게 **"표본 문제는 해결되지 않았다"로
기록한다.** 이번 측정의 존재 이유가 그것이므로, 일치율이 좋게 나와도 이 조건이
깨지면 결론을 강하게 읽지 않는다.

**임계값을 튜닝하지 않는다. 규칙을 추가하지 않는다. 런을 골라내지 않는다.**

## 이번 표본이 앞선 26 건보다 나은 점 하나

새 런은 LLM judge 가 제거된 코드(`5e8ca28`)에서 돌아간다. 앞선 표본의 오염 사례
(`pvt_verification_1`: measurements 가 비어 LLM 이 `actual=0` 을 지어낸 건)는
구조적으로 재발할 수 없다. 판정 경로가 이제 `evaluate_criteria` 이고 값이 없으면
`NaN` 을 쓰기 때문이다. 분류 (a) 는 새 표본에서 나오지 않을 것으로 예상하지만,
**예상은 규칙이 아니므로 (a) 항목은 그대로 둔다.**
