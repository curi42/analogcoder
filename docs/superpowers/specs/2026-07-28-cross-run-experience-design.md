# 런 간 경험 (하위 프로젝트 D) — 설계

## 문제, 그리고 로드맵을 다시 쓰게 만든 실측

로드맵의 D는 "과거 튜닝 시도에서 학습"이었고, 조사 단계에서 전이 학습(multi-task
GP, RGPE)과 "LLM 위키"를 후보로 적어 뒀다. **전부 데이터를 전제한다.**

실제 코퍼스를 세어 봤다:

```
런 10개 · 튜닝 제안 총 35건 · 기록된 결과 23건 (keep 16 / rollback 7)
result: PASS 6, FAIL 3
가장 큰 런이 102 이벤트, 나머지는 9~19
```

그리고 결정적인 사실: **10개 런 전부가 `analysis:1` 이벤트를 갖고 있다.** 그것은
E2에서 **삭제된** analyzer 에이전트다. 현재 파이프라인이 남기는 이벤트 —
`focus`, `param_check`, `stimulus_check`, `optimize_*`, `corner_*`,
`topology_candidates` — 는 **한 번도 나타나지 않는다.**

즉 **현재 코드로 돌아간 런은 0개다.** 낡은 것까지 세어도 제안 35건은
데이터셋이 아니라 일화다. 게다가 이벤트가 학습에 필요한 것을 담고 있지 않다:
`tuning_proposal`은 `{refdes, param, old_value, new_value, reasoning}`이고,
**어느 스펙·어느 회로에 대한 제안인지가 이벤트 스트림 안에 없다.** 런 디렉터리
이름으로만 알 수 있다.

그래서 D는 "과거에서 배운다"가 아니라 **"런이 배울 수 있는 것을 남기게 만든다"**
이다. 예측 모델도, 순위도, 요약 에이전트도 넣지 않는다 — 근거 없이 상태를
늘리는 것은 이 저장소가 코너 축소에서 대리 모델을, F2에서 회로 클래스 축을
보류한 것과 같은 판단이다. 35건으로 워스타트를 만드는 것은 **bandit을 기각한
것과 같은 종류의 오류**다(결정론적 평가에 통계적 도구를 붙이는 것 ↔ 없는
데이터에 학습기를 붙이는 것).

## 범위

**D에 들어가는 것**

- **경험 저장소**: 기계 판독 가능한 append-only 기록. 한 항목 = 한 번의 시도
  = (상황, 행동, 결과).
- **결정론적 회로 지문**: `structure.py`/`patterns.py`에서 파생. 값에 불변.
- **정확 일치 회상**: 지문·기준·노브가 **정확히** 같을 때만 튜너 프롬프트에
  사실로 들어간다.
- **IP 경계**: 저장소 루트 밖의 스펙에서 나온 항목은 커밋 대상 저장소에
  들어가지 않는다.
- **코퍼스 생성**: 벤치마크를 현재 파이프라인으로 실제로 돌려 첫 코퍼스를
  만들고, 회상이 무엇을 하는지 **측정해서 보고**한다.

**D에 들어가지 않는 것**

- 예측 모델, 워스타트, 노브 순위. 데이터가 생긴 뒤의 문제다.
- 느슨한 유사도 매칭. 아래 "정확 일치만" 참고.
- 경험을 읽고 요약하는 에이전트. analyzer가 삭제된 이유와 같은 모양이므로,
  **측정 가능한 기여를 먼저 보인 뒤에**만 도입한다.
- 과거 실행 로그의 소급 수집. 10개 런은 삭제된 에이전트 시대의 것이라
  현재 파이프라인의 상황을 식별할 수 없다. 마이그레이션하지 않고 **왜 안
  하는지를 기록**한다.

## 경험의 단위

한 항목은 **한 번의 시도**다. 이터레이션도 런도 아니다 — 다음 런이 알고 싶은
것은 "이 회로의 이 기준에 대해 이 노브를 이렇게 움직였더니 이렇게 됐다"이기
때문이다.

```python
@dataclass(frozen=True)
class Attempt:
    # 상황 - 무엇을 고치려 했는가
    circuit: str          # 회로 지문 해시
    criterion: str        # 기준 이름
    target: str           # 연산자 + 임계값 (">=60.0")
    actual_before: float | None

    # 행동 - 무엇을 했는가
    refdes: str           # 스코프 한정 (예: "TRIMAMP.XRz")
    param: str
    old_value: str
    new_value: str

    # 결과 - 무엇이 일어났는가
    gate: str | None      # 결정론적 게이트가 막았다면 그 사유 코드
    outcome: str          # "kept" | "rolled_back" | "gate_rejected"
    deltas: dict[str, float]   # 기준 이름 -> 변화량 (적용됐다면)
    regressed: list[str]       # verify_post가 회귀로 지목한 기준들

    # 출처
    spec: str             # 스펙 경로 (저장 위치 판정에 쓰인다)
    run: str              # 런 디렉터리 이름
```

**`reasoning`은 저장하지 않는다.** LLM이 쓴 산문이고, 다음 런의 프롬프트에
넣으면 검증되지 않은 주장이 사실인 척 들어간다 — F2가 `addresses`를 에이전트가
쓰게 두지 않은 것과 같은 이유다. 무엇을 했고 무엇이 일어났는지만 남긴다.

**게이트 거부도 항목이다.** 에어리어 게이트가 막은 제안은 "이 노브를 이만큼
키우는 것은 이 회로에서 허용되지 않는다"는 사실이고, 그것은 시뮬레이션 없이
얻은 진짜 정보다. 실제 런에서 이 게이트가 튜너의 전략을 바꾼 기록이 이미 있다
(`BUF_P.Xcl` 거부 후 다음 재시도에서 `BUF_P.X6`로 이동).

## 회로 지문

`structure.py`와 `patterns.py`가 이미 결정론적으로 내는 것에서 파생한다.
실측한 재료:

```
bandgap/netlist_loops.cir
  blocks   : BANDGAP BGR_CORE BUF_N BUF_P ERRAMP TRIMAMP
  ports    : 블록별 포트 목록
  classes  : 블록별 device_class 카운트 (예: {'X':4, 'res':4})
  patterns : current_mirror 2, diff_pair 4, stacked_pair 16

two_stage_opamp/netlist.cir
  blocks   : OPAMP2STAGE
  classes  : {'pfet':6, 'nfet':5, 'R':2, 'cap':2}
  patterns : current_mirror 4, diff_pair 1, miller_compensation 1
```

**값(`W`/`L`/`m`)은 지문에 넣지 않는다.** 넣으면 튜닝이 한 번만 일어나도 지문이
바뀌어 회상이 영원히 빗나간다. 위 재료는 전부 **값 튜닝에 불변**이다.

**토폴로지 스왑은 지문을 바꾼다. 그것이 옳다** — 스왑 후에는 블록 구성과 패턴이
실제로 달라졌으므로 다른 회로이고, 스왑 전의 경험을 그대로 적용하면 안 된다.

지문은 **해시와 사람이 읽을 요약을 둘 다** 저장한다. 해시는 정확 일치용,
요약은 저장소를 사람이 열어 봤을 때 무엇인지 알기 위한 것이다.

## 정확 일치만

회상은 `(circuit, criterion, refdes, param)`이 **정확히** 같을 때만 일어난다.

느슨한 유사도 — "비슷한 회로", "비슷한 기준" — 는 넣지 않는다. 이 저장소는
이름으로 의미를 알아보는 것을 금지하고, 회로 사이의 "유사도"는 그보다 더 큰
추측이다. `patterns.py`가 캐스코드를 `stacked_pair`라고만 부르는 이유와 같다:
그래프가 증명하는 것만 주장한다.

정확 일치가 좁다는 것은 인정하고 **측정해서 기록한다** — 코퍼스가 쌓인 뒤
"회상이 몇 번 발동했는가"가 다음 단계(느슨한 매칭이 필요한지)의 근거가 된다.
근거를 만들기 전에 상태를 늘리지 않는다.

## 소비 — 튜너 프롬프트에 사실로

일치하는 항목이 있으면 튜너 프롬프트에 사실 목록으로 들어간다:

```
Previously attempted on this exact circuit and criterion:
- TRIMAMP.XRz.l 15 -> 45 : kept, phase_margin +18.4
- TRIMAMP.XRz.l 15 -> 90 : gate_rejected (area, 6.00x exceeds the 3.0x limit)
- BUF_P.Xcl.W  20 -> 150 : rolled_back, regressed [vbg0_droop]
```

**프롬프트는 이것을 지시가 아니라 사실로 제시한다.** "이걸 하지 마라"가 아니라
"전에 이렇게 했더니 이렇게 됐다". 튜너는 여전히 현재 넷리스트를 보고 스스로
판단한다 — 과거의 롤백이 지금도 롤백이라는 보장은 없기 때문이다(회로의 다른
곳이 그 사이에 바뀌었을 수 있다).

**프롬프트에 넣는 항목 수에 상한을 두고, 잘랐으면 잘랐다고 적는다.** 조용한
절삭은 이 저장소가 반복해서 값을 치른 모양이다.

## 저장 위치와 IP 경계

기본 경로는 저장소 안의 `experience/`이고 **커밋한다.** 원격이 없어도 커밋은
세 가지를 준다: `git clean`에도 살아남는 지속성, diff로 리뷰 가능함, 저장소가
복사·이동될 때 함께 감. 원격이 없으면 사람들 사이의 공유만 안 된다.

**IP 경계는 구조로 막는다.** 항목은 자기가 나온 스펙 경로를 갖는다. **그 스펙이
저장소 루트 밖에 있으면** 항목은 커밋 대상 `experience/`가 아니라 git이 무시하는
로컬 저장소로 간다. 경로 포함 여부는 추측이 아니라 파스된 사실이다.

이것이 필요한 이유는 구체적이다: 이 공개 저장소를 체크아웃해 생산 덱을 돌리면,
지문 요약과 refdes(`xwrap1.wn` 같은 래퍼 셀 명명)가 그대로 항목에 들어간다.
사용자는 이미 생산 넷리스트 샘플을 **저장소에 두지 말라**고 명시한 적이 있다.
`--experience-dir`로 명시적으로 다른 경로를 지정할 수도 있다.

## 산출물 — 마크다운은 파생물이다

기계 판독 가능한 저장소가 진실의 출처이고, 사람이 읽는 요약은 **거기서
생성**된다. 반대가 되면 두 개가 갈라지고, 그때 어느 쪽이 맞는지 아무도 모른다.

- `experience/attempts.jsonl` — append-only, 한 줄 한 항목
- `experience/circuits.json` — 지문 해시 → 사람이 읽을 요약
- `experience/DIGEST.md` — 위 둘에서 **생성**되는 읽기용 요약. 손으로 고치지
  않는다. 재생성 명령이 헤더에 적혀 있다.

## 코퍼스 생성 — 이 하위 프로젝트가 자기 전제를 만든다

D는 데이터가 없다는 사실 위에 서 있으므로, **데이터를 만드는 것까지가 범위다.**
현재 파이프라인으로 벤치마크를 실제로 돌려 첫 코퍼스를 만든다:

- `benchmarks/bandgap`의 세 시드 스펙(`trim_pm`, `tc`, `buf0_droop`) — 각각
  의도된 블록으로 수렴하는 것이 이미 확인된 것들
- `benchmarks/two_stage_opamp/spec.yaml`
- 같은 시드를 **두 번씩** — 두 번째 실행이 첫 번째의 항목을 회상하는지가
  이 하위 프로젝트의 종단 증명이다

**측정해서 보고할 것:** 생성된 항목 수, 회상이 발동한 횟수, 그리고 회상이
실제로 다른 행동을 낳았는지. **개선을 주장하지 않는다** — 이 저장소는 측정된
것만 적는다. 회상이 아무 행동도 바꾸지 않았다면 그것도 결과이고, 그 사실이
느슨한 매칭이나 순위가 필요한지에 대한 근거가 된다.

## 과거 런을 마이그레이션하지 않는 이유

기존 10개 런은 `analysis` 이벤트를 갖는다 — 삭제된 에이전트 시대의 것이다.
그 시대에는 `focus`도 `param_check`도 없었고, 무엇보다 **이벤트에 스펙·회로
정체성이 없다.** 지문을 소급해서 만들려면 그 런이 어느 넷리스트를 썼는지를
런 디렉터리 이름에서 **추측**해야 하고, 그것은 이 저장소가 금지하는 종류다.

35건을 살리려고 추측을 들이는 것보다, 현재 파이프라인으로 새로 만드는 편이
싸고 정직하다. 이 문단이 "왜 안 했는지"의 기록이다.

## 에러 처리

경험 기록은 **런을 실패시키지 않는다.** 저장소를 못 쓰거나(디스크, 권한),
읽다가 깨진 줄을 만나거나, 지문 파생이 실패해도 런은 계속되고 그 사실이
`history.jsonl`에 남는다. 경험은 보조 정보이지 파이프라인의 의존성이 아니다 —
`run_optimization`의 가드와 같은 규율이다.

깨진 줄 하나가 파일 전체를 못 쓰게 만들면 안 되므로 `attempts.jsonl`은
줄 단위로 읽고 파싱 실패한 줄은 세어서 로그로 낸다(조용히 건너뛰지 않는다).

## 로깅

- `experience_recorded` — 항목 수, 저장 위치(커밋 대상인지 로컬인지), 그리고
  로컬로 간 경우 그 이유
- `experience_recall` — **무조건** 기록한다. 일치 0건이어도 "조회했고 0건"과
  "조회 자체가 사라졌다"가 구별되어야 한다. 조회 키, 일치 수, 프롬프트에 넣은
  수, 잘랐다면 잘린 수
- `experience_unavailable` — 저장소를 못 읽었을 때, 사유와 함께

## 테스트

1. `tests/unit/test_experience.py` — 항목 직렬화, append-only, 깨진 줄이 파일을
   무효화하지 않고 카운트되는 것.
2. `tests/unit/test_circuit_fingerprint.py` — **값 불변성이 핵심이다**:
   같은 덱의 `W`/`L`/`m`을 바꿔도 지문이 같고, 블록을 추가하거나 토폴로지를
   스왑하면 달라진다. 두 벤치마크 덱의 지문이 서로 다르다.
3. `tests/unit/test_experience_recall.py` — 정확 일치만 회상된다(기준이 다르면
   0건, refdes가 다르면 0건, 지문이 다르면 0건), 상한을 넘으면 잘린 수가
   기록된다.
4. **IP 경계 테스트** — 저장소 루트 밖의 스펙에서 나온 항목이 커밋 대상
   저장소에 **쓰이지 않는다**. 이 하위 프로젝트에서 조용히 사라지면 가장
   비싼 회귀이므로 변형으로 고정한다.
5. `tests/unit/test_tuner_agent.py` (확장) — 회상된 사실이 프롬프트에 들어가고,
   일치가 없으면 그 절이 아예 없다(빈 절을 그리지 않는다).
6. **종단** — 같은 시드 스펙을 두 번 돌려 두 번째가 첫 번째의 항목을 회상하는
   것. LLM 없이 결정론적으로 검증할 수 있는 형태로 만든다.

새 테스트마다 "이 테스트는 어떤 변형을 잡는가"를 답하고, **변형을 실제로 적용해
확인**한다.

## 성공 기준

1. 현재 파이프라인으로 돈 런이 항목을 남기고, 같은 회로·같은 기준의 두 번째
   런이 그것을 회상한다.
2. 회상은 정확 일치일 때만 일어나고, 조회 사실은 일치 0건이어도 로그에 남는다.
3. 저장소 루트 밖의 스펙에서 나온 항목은 커밋 대상 저장소에 들어가지 않는다.
4. 경험 계층의 어떤 실패도 런을 실패시키지 않는다.
5. `DIGEST.md`가 기계 판독 저장소에서 생성되며, 손으로 고친 흔적이 있으면
   재생성이 그것을 덮어쓴다.
6. 코퍼스 생성 실행의 **측정된 결과**가 기록된다 — 항목 수, 회상 발동 횟수,
   그리고 회상이 행동을 바꿨는지. 바꾸지 않았다면 그것도 결과로 적는다.
